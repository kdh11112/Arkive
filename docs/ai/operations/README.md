# 4차 운영 절차 현황

이 폴더는 Arkive의 실제 배포·운영 Runbook 위치와 확인 상태를 정리한다. 확인되지 않은 운영 정보를 추정해 실행 절차로 만들지 않는다. 보안 연락처, 계정, 비밀값은 문서에 저장하지 않는다.

## 현재 상태

| 운영 항목 | 현재 확인 상태 | 정식 문서화에 필요한 정보 |
| --- | --- | --- |
| 배포 | 도구, 대상 환경, 승인과 순서 미확인 | 환경별 artifact/설정, 사전 점검, 승인자, 배포·사후 확인 단계 |
| 롤백 | 절차와 복구 책임자 미확인 | 트리거, 코드/설정 복원, DB 호환성·복구, 검증, 담당자 |
| Migration | [프로젝트 마이그레이션 현황](../project/migration.md)에 버전형 SQL 실행과 운영 미확인 사항 기록. V4는 과거 샘플 테이블을 삭제함 | 실제 운영 도구, 적용 대상·순서, 백업, 승인 및 검증 결과 |
| Health | Actuator 의존성은 있으나 운영 endpoint, 지표, 임계치는 미확인 | Liveness/Readiness 기준, 점검 URL, 임계치, 모니터링 위치와 대응자 |
| Error monitoring | 프로젝트 오류 코드/예외 현황은 [error-code.md](../project/error-code.md)에 기록. 대시보드·알림·당직 경로 미확인 | 로그/대시보드 위치, 알림 조건, 담당자, 개인정보 마스킹 기준 |
| Canary | 배포 플랫폼과 점진 배포 지원 여부 미확인 | 지원 여부, 트래픽 단계, 관찰 지표·시간, 진행/중단 기준, 복구 방법 |

## Runbook 기록 기준

운영 절차를 확인한 뒤 필요한 항목만 별도 문서로 만든다. 각 Runbook에는 대상 환경과 버전, 실행 전제·승인, 명령/단계, 성공 판정, 실패 시 중단·복구, 담당 역할, 검증 증거와 최종 확인일을 기록한다. 비밀값 대신 안전한 비밀 저장소의 참조만 사용한다.

Canary는 실제 플랫폼이 지원하고 운영 담당자가 진행·중단 기준을 정한 경우에만 별도 절차를 둔다. Health 기준도 담당자가 확인한 서비스 수준에 맞춰 문서화한다. 준비되지 않은 항목은 `미확인`으로 유지하며 활성화된 운영 절차처럼 표현하지 않는다.
