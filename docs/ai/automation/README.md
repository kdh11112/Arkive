# 3차 AI 자동화 현황

> 이식 구분: 선택. 이식용 아카이브에 필수가 아니다. 방법은 `common/verification-standard.md`를 복붙하고, 실행 도구는 대상 프로젝트에서 필요할 때 만든다.

이 폴더는 자동 검증·변경 통제 도구의 실제 구현과 프로젝트별 설정을 추적한다. 현재 공통 방법은 [verification-standard.md](../common/verification-standard.md), 테스트 방법은 [test-standard.md](../common/test-standard.md)에 정의되어 있다. 아래 방법 문서가 있다는 사실은 실행 가능한 도구가 구현되었다는 뜻이 아니다.

## 구현 상태

| 항목 | 방법/근거 | 현재 저장소에서 확인된 상태 | 구현에 필요한 프로젝트별 결정 |
| --- | --- | --- | --- |
| Verifier | Acceptance Criteria 및 프로젝트 계약을 기준으로 기대·실제를 비교 | 공통 절차만 문서화. 자동 검증기 미확인 | 자동화 대상 기능, 정답 데이터 출처, 허용 오차, 실행 환경 |
| Guard | 변경 전 보안·데이터·계약·범위 위험을 확인 | 공통 검토 절차만 문서화. Hook/CI 차단 도구 미확인 | 차단 조건, 승인 예외, 실행 위치(CI/로컬 등) |
| Baseline | 변경 전 버전·환경·데이터 조건을 비교 기준으로 기록 | SHA/Revision 및 조건 기록 방법은 있음. 기능별 기준 관리 방식 미확인 | 기준 버전, 테스트 데이터, 갱신 승인자 |
| Snapshot | 변경 전 화면·응답·DB 등 필요한 상태를 보존 | 안전한 보존 방법만 문서화. 수집 도구/저장소 미확인 | 수집 대상, 마스킹, 접근권한, 보관 위치·기간 |
| Runtime verification | 실제 화면/DOM·API·DB·로그 확인 | 확인 절차만 문서화. 브라우저/API/DB 자동 실행 도구 미확인 | 지원 환경, 테스트 계정/데이터, 안전한 접속 방법 |

## 도구를 추가할 때 기록할 정보

- 도구 이름, 저장 경로, 버전 및 실행 명령
- 검사 입력과 결과 기준의 출처
- 자동으로 확인하는 범위와 확인하지 않는 범위
- 성공/실패 기준, 실패 시 작업 중단 또는 알림 방식
- 테스트 데이터, 비밀정보 처리와 생성 증거의 저장 위치
- 실행 환경, 담당자 및 유지보수 방법

실제 CI 설정이나 스크립트가 추가되면 이 표를 갱신하고, 성공·실패 사례로 동작을 확인한다. 도구가 없는 항목은 문서 절차로만 표시한다.
