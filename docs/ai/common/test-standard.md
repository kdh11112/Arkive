# 공통 테스트 및 검증 표준

변경 범위와 위험도에 맞는 검증을 선택한다. 모든 변경에 모든 종류의 테스트를 강제하지 않으며, 수행하지 않은 검증을 통과했다고 표현하지 않는다. 프로젝트에 기존 테스트 도구와 실행 방식이 있으면 이를 우선한다.

Baseline, Snapshot, Verifier와 Runtime 검증의 공통 절차는 [verification-standard.md](verification-standard.md)를 따른다. 기대 결과와 테스트 사례는 관련 프로젝트 정책, 계약 및 Acceptance Criteria에서 확인한다.

## 기본 확인 항목

해당되는 경우 다음 상황을 고려한다.

- 정상 입력 및 정상 흐름
- 필수값 누락, 잘못된 형식, 허용 범위 및 길이 경계
- 권한 없는 접근과 직접 URL/API 요청
- 중복 요청 및 허용되지 않는 업무 상태
- 외부 연계, DB 오류, 예외 및 트랜잭션 롤백
- 기존 기능과 공통 모듈에 대한 회귀 영향

화면에서 버튼을 숨기는 것만으로 권한 검증이 완료되었다고 판단하지 않는다. 가능한 경우 서버 측에서 직접 요청에 대한 접근 제한도 확인한다.

## 변경 범위별 검증

- 화면/JSP/Thymeleaf/CSS: 렌더링, 사용자 입력과 동작, 버튼 상태 및 브라우저 콘솔을 확인한다.
- JavaScript/AJAX: 정상·잘못된 입력, 이벤트, 성공·오류 응답, 요청/응답 내용, 콘솔 및 네트워크 결과를 확인한다.
- Controller/API: 정상 요청, 필수값 누락과 잘못된 값, 권한, 응답 구조, HTTP 상태 및 오류 응답을 확인한다.
- Service/업무 규칙: 정상·예외 흐름, 업무 규칙, 상태 전이, 트랜잭션 처리와 DB 결과를 확인한다.
- Mapper/SQL: 정상 조회, 조건 누락, NULL, 중복/집계, 페이징, 대상 DB 문법 및 UPDATE/DELETE 대상 범위를 확인한다.
- 스키마/초기화 스크립트: 변경 전후 구조, 기존 데이터와 기능 영향, 기존 SQL 영향, 배포 순서 및 복구/롤백 가능성을 확인한다.

변경된 계층에 해당하는 항목을 선택하고, 관련 없는 항목은 `N/A`로 처리한다.

## 예외 및 데이터 안전

- 가능한 경우 DB 제약조건, 외부 API, 네트워크, 서버 예외 및 트랜잭션 롤백 상황을 확인한다.
- 장애를 의도적으로 발생시키는 검증은 운영 환경에서 수행하지 않는다. 테스트 DB, Mock 또는 통제된 환경을 사용한다.
- 테스트 데이터는 운영 데이터와 분리하고, 테스트 후 정리 필요 여부와 정리 결과를 확인한다. 테스트가 기존 데이터에 영향을 줄 수 있으면 실행 전 대상과 복구 방법을 확인한다.

## 실행과 기록

- 저장소에 테스트가 있으면 변경과 관련된 테스트를 우선 실행한다. 변경 범위와 위험도에 따라 빌드, 정적 확인, 자동 테스트, Runtime 검증을 선택한다.
- 테스트가 없거나 실행 환경이 준비되지 않았다면 가능한 검증을 수행하고 제한 사항과 미수행 사유를 기록한다.
- 테스트 결과에는 가능한 경우 테스트 항목, 입력/실행 조건 또는 명령, 기대 결과, 실제 결과, 판정 및 근거 위치를 남긴다.
- 판정은 `통과`, `실패`, `N/A`, `미수행`을 구분한다. 실패 또는 미수행 항목이 있으면 원인과 완료 판단에 미치는 영향을 기록한다.
- 화면, API, 서버, DB 등 Runtime 확인은 변경 특성에 맞는 범위에서 수행한다. 소스가 정상으로 보인다는 이유만으로 실행 검증을 완료했다고 판단하지 않는다.
- 중요한 변경의 실행 근거를 남길 필요가 있으면 [evidence-report-template.md](evidence-report-template.md)를 사용한다.

## 회귀 검증

공통 Mapper, Service, 권한, API 응답, DB 컬럼 또는 공통 UI를 변경하면 사용처를 찾아 회귀 범위를 넓힌다. 변경된 공통 기능을 호출하는 주요 화면과 기능이 기존처럼 동작하는지 확인한다.

## 테스트 완료 판단

완료 여부를 판단할 때 다음을 확인한다.

- 요구사항과 Acceptance Criteria가 충족되었는가
- 잘못된 입력과 예외가 적절히 처리되는가
- 권한과 데이터 정합성이 유지되는가
- 기존 기능에 문제가 없는가
- 필요한 Runtime 검증이 수행되었는가
- 실패·미수행 검증의 영향과 남은 위험이 기록되었는가
