# 공통 테스트 및 검증 표준

> 이식 구분: 가이드형. 파일째 복사하되, 적용할 때는 프로젝트 테스트 환경 값으로 판단한다.

변경 범위와 위험도에 맞는 검증을 선택한다. 모든 변경에 모든 종류의 테스트를 강제하지 않으며, 수행하지 않은 검증을 통과했다고 표현하지 않는다. 프로젝트에 기존 테스트 도구와 실행 방식이 있으면 이를 우선한다.

이 문서는 테스트 선택·GUI·판정 기준을 관리한다. 실행 안전성·Baseline·Snapshot·증거 수집 절차는 [verification-standard.md](verification-standard.md), 기대 결과는 프로젝트 정책·계약·Acceptance Criteria를 따른다.

테스트 스택(pom·CI·뼈대)은 [이식 가이드](../../../PORTING.md)의 선택 트랙을 따른다. 대상에 없는 반대 트랙은 참고 경로일 뿐 필독 문서가 아니다.

## 기본 확인 항목

해당되는 경우 다음 상황을 고려한다.

- 정상 입력 및 정상 흐름
- 필수값 누락, 잘못된 형식, 허용 범위 및 길이 경계
- 권한 없는 접근과 직접 URL/API 요청
- 중복 요청 및 허용되지 않는 업무 상태
- 외부 연계·네트워크·DB 제약조건/오류, 예외 및 트랜잭션 롤백
- 기존 기능과 공통 모듈에 대한 회귀 영향

화면에서 버튼을 숨기는 것만으로 권한 검증이 완료되었다고 판단하지 않는다. 가능한 경우 서버 측에서 직접 요청에 대한 접근 제한도 확인한다.

## 이식 시 테스트 자산

- 테스트 준비·맞춤 수정은 스펙 담당자의 별도 작업이며 기대 결과·assertion 변경에는 인간 승인이 필요하다. 구현 에이전트는 테스트 파일을 만들거나 수정하지 않고 필요한 자산·변경점만 보고한 뒤 제공된 테스트로 검증한다. 대상 루트 `AGENTS.md`가 우선한다.
- 테스트가 없거나 준비되지 않았으면 이식을 완료로 보고하지 않는다. 이식 안내·예제는 테스트 수정 권한을 부여하지 않는다.
- 테스트 DB는 운영 DB와 분리하고, 대상 DB 제품이 HSQLDB와 다르면 같은 제품으로 Mapper/SQL을 검증한다.
- 기능 실행·화면/API/DB 결과는 [기능 시트](../portable/feature-porting-sheet.md), 테스트 복사·맞춤·검증 결과는 [테스트 시트](../portable/test-porting-sheet.md)에 남긴다.
- 테스트를 삭제·skip하거나 빈 테스트로 커버리지 숫자만 맞추지 않는다.

## 변경 범위별 검증

| 변경 | 확인할 항목 |
| --- | --- |
| 화면/JSP/Thymeleaf/CSS | 렌더링, 입력·동작, 버튼 상태, 콘솔 |
| JavaScript/AJAX | 정상·잘못된 입력, 이벤트, 성공·오류 응답, 요청/응답, 콘솔·네트워크 |
| Controller/API | 정상·잘못된 요청, 필수값, 권한, 응답 구조·HTTP 상태·오류 |
| Service/업무 규칙 | 정상·예외 흐름, 정책·상태 전이, 트랜잭션·DB 결과 |
| Mapper/SQL | 정상 조회·조건 누락·NULL·중복/집계·페이징, 대상 DB 문법, 변경 행 범위 |
| 스키마/초기화 | 전후 구조, 기존 데이터·기능·SQL 영향, 배포 순서·복구 가능성 |
| 문서/Markdown | 링크·제목 앵커·코드 블록, 원본 대조, 규칙·상태·출처·검증 이력 보존 |

변경된 계층에 해당하는 항목을 선택하고, 관련 없는 항목은 `N/A`로 처리한다.

## 검증 단계와 GUI 확인

검증은 아래 순서로 쌓는다. GUI가 실제 사용자에 가장 가까운 최상위 단계다.

| 단계 | 확인 대상 | 예 |
| --- | --- | --- |
| 1. 단위 | 함수·계산·정책 | 일수 계산, 권한 판정 |
| 2. 통합/API | Controller·Service·Mapper·DB | MockMvc, DB 통합 테스트 |
| 3. Runtime/HTTP | 기동한 앱의 실제 응답 | 세션 로그인, 화면·API 응답 코드, JSON 흐름 |
| 4. GUI/E2E (최상위) | 실제 브라우저의 렌더링·JavaScript·AJAX·권한·사용자 흐름 | 로그인→신청→승인→취소를 화면에서 수행, 콘솔·네트워크·DB 결과 확인 |

- 회귀 방지는 재현 가능한 하위 자동 테스트가 담당하며 GUI 확인이 이를 대체하지 않는다.
- GUI 확인은 ego-browser로만 수행한다. 다른 브라우저 자동화나 데스크톱 앱 자동화(computer-use 등)로 대체하지 않는다. ego-browser가 설치되지 않았거나 실행할 수 없으면 GUI 확인은 `미수행`으로 기록하고, 설치·온보딩 후 다시 수행한다.
- GUI 확인을 수행했다면 URL, 계정·권한, 입력 데이터, 기대/실제 결과, 화면 증거(관찰 결과·DOM·필요 시 스크린샷), 테스트 데이터 정리 여부를 기록한다. 원본 로그·이미지는 재현·시각 확인에 필요한 범위만 보관하며, 파일 존재 자체로 GUI 완료를 판정하지 않는다. 수행하지 못했다면 `미수행`과 사유를 남기고 GUI 확인 완료로 표시하지 않는다.
- 기록 표시는 자동 테스트와 GUI 확인(ego-browser)을 모두 마친 항목에 `[검증완료]`를 붙이는 것으로 한다. 두 축을 모두 마치지 않은 항목에는 표시를 붙이지 않고, 남은 검증과 사유를 기록한다.

### 화면 크기 확인

- 화면/CSS 변경은 **13.3인치 노트북에서 필수 확인**한다. 실제 기기의 해상도, OS 표시 배율, 브라우저 확대율, viewport 폭×높이(CSS px)를 증거에 기록한다. 인치에서 해상도를 추정하지 않는다.
- 24·30인치 등 나머지 화면은 고정 인치별 구현 조건이 아니라 유동 대응 범위다. 큰 폭·중간 폭·줄인 창과 사용 환경의 배율에서 주요 화면이 자연스럽게 대응하는지 확인한다. 예시 viewport는 실기기 조건을 대신하지 않는다.
- 목록·검색·등록/수정·상세·사이드바·모달에서 필수 정보와 조작 버튼이 잘리지 않고, 차트/텍스트가 겹치지 않으며, 불필요한 페이지 가로 스크롤이 없는지 확인한다. 넓은 표의 전용 스크롤 등 의도한 예외는 범위·사용성을 별도 기록한다.
- ego-browser의 viewport 조정은 대체 폭 검사로 기록한다. 실제 13.3인치 기기를 확인하지 못했으면 그 필수 항목은 `미수행`과 사유·추가 확인 조건을 남기며 완료로 표시하지 않는다.

CSS 작성 기준은 [coding-standard.md](coding-standard.md#css반응형-화면)를 따른다.

## 예외 및 데이터 안전

- 장애를 의도적으로 발생시키는 검증은 운영 환경에서 수행하지 않는다. 테스트 DB, Mock 또는 통제된 환경을 사용한다.
- 테스트 데이터는 운영 데이터와 분리하고, 테스트 후 정리 필요 여부와 정리 결과를 확인한다. 테스트가 기존 데이터에 영향을 줄 수 있으면 실행 전 대상과 복구 방법을 확인한다.

## 실행과 기록

- 관련 테스트를 우선 실행하고 범위·위험도에 맞게 빌드·정적 확인·Runtime 검증을 선택한다. 작업 마무리에는 루트 `AGENTS.md`의 필수 검증 명령과 관문을 따른다.
- 테스트가 없거나 실행 환경이 준비되지 않았다면 가능한 검증을 수행하고 제한 사항과 미수행 사유를 기록한다.
- 테스트 결과에는 가능한 경우 테스트 항목, 입력/실행 조건 또는 명령, 기대 결과, 실제 결과, 판정 및 근거 위치를 남긴다.
- 판정은 `통과`, `실패`, `N/A`, `미수행`을 구분한다. 실패 또는 미수행 항목이 있으면 원인과 완료 판단에 미치는 영향을 기록한다.
- Runtime 확인의 실행 안전성과 증거 수집은 [검증 절차](verification-standard.md#runtime-검증), 기록 양식은 [Evidence](../portable/evidence-report-template.md)를 따른다. 소스 검토만으로 실행 검증을 완료했다고 판단하지 않는다.

## 회귀 검증

공통 Mapper, Service, 권한, API 응답, DB 컬럼 또는 공통 UI를 변경하면 사용처를 찾아 회귀 범위를 넓힌다. 변경된 공통 기능을 호출하는 주요 화면과 기능이 기존처럼 동작하는지 확인한다.

## 테스트 완료 판단

완료 여부를 판단할 때 다음을 확인한다.

- 요구사항·Acceptance Criteria가 충족되고, 잘못된 입력·예외 처리와 권한·데이터 정합성이 유지되는가
- 관련 테스트와 기존 기능 회귀가 통과했는가
- 필요한 Runtime 검증과 화면 변경의 GUI 확인이 수행되었는가
- 실패·미수행 검증의 사유, 완료 판단에 미치는 영향과 남은 위험이 기록되었는가
