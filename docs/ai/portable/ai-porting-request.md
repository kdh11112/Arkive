# AI에게 이식 요청하는 방법

> 이 문서는 Arkive 기능을 다른 프로젝트로 이식할 때 AI에게 어떻게 요청하고,
> Arkive와 대상 프로젝트를 어디에 두는지 설명한다.
> 한 번에 전체를 이식하지 말고 **기능 하나씩** 요청한다.

## 1. 권장 배치

Arkive와 대상 프로젝트는 **형제 폴더**에 두는 것을 권장한다.

```text
C:\work\
  Arkive\            ← 레퍼런스, 읽기 전용으로 취급
  target-project\    ← 실제 작업 디렉터리
```

- AI 세션은 **대상 프로젝트에서 시작**한다.
- 프롬프트에 Arkive의 **절대 경로**를 적는다.
- 대상 프로젝트 안에 Arkive를 복사하거나 커밋하지 않는다.
  - 검색·빌드·커밋에 Arkive 파일이 섞일 수 있다.
- AI가 두 경로를 모두 읽을 수 있으면 **MD를 수동으로 옮길 필요가 없다.**

## 2. 수동 복사가 필요한 경우

| 상황 | 방법 |
| --- | --- |
| AI가 Arkive와 대상 프로젝트를 모두 읽을 수 있음 | 대상 프로젝트를 작업 디렉터리로 열고 Arkive 절대 경로만 알려준다. MD 수동 복사 불필요 |
| AI가 Arkive를 읽을 수 없음 | [5분 복사](../../../PORTING.md#1-5분-복사-windows)를 먼저 실행한다 |
| 다른 PC·다른 저장소 | 필요한 문서와 코드만 복사한 뒤, 대상 프로젝트에서 AI 세션을 시작한다 |

복사 목록·제외 범위는 [PORTING.md의 복사 선택표](../../../PORTING.md#0-결론-복사할-것과-복사하지-않을-것), 위험한 복사의 금지 기준은 [하지 말 것](../../../PORTING.md#7-하지-말-것) 한 곳에서 관리한다. 기존 대상 파일을 임의로 덮어쓰지 않으며 Arkive 기록·로컬 DB 파일·비밀값을 가져오지 않는다.

대상의 기존 프로젝트 지식을 재사용하고, 없을 때만 [빈 양식](project-template-pack.md)으로 작성한다.

## 3. 따라하기

### 3.1 준비

- [ ] Arkive와 대상 프로젝트를 형제 폴더에 둔다.
- [ ] 대상 프로젝트를 AI의 작업 디렉터리로 연다.
- [ ] Arkive의 절대 경로를 확인한다.
- [ ] 대상 프로젝트의 패키지·DB 제품·인증 방식을 확인한다.
- [ ] 이번에 이식할 기능 하나를 정한다.
- [ ] 위 표로 수동 복사가 필요한지 결정한다.

### 3.2 요청

아래 프롬프트를 복사해 경로와 기능명만 바꾼다.

```text
Arkive 레퍼런스: C:\work\Arkive
대상 프로젝트: 현재 작업 디렉터리 (C:\work\target-project)

이번 이식 기능: 게시판 댓글
범위: 화면 + Controller + Service + Mapper/XML + SQL + 테스트

1. 대상 루트 AGENTS.md를 따르고, Arkive의 PORTING.md와 해당 기능에 필요한 문서만 읽어라.
2. Arkive를 실행해 ego-browser로 댓글 등록·삭제·권한 동작을 확인하고, 대상과 다른 점을 표로 정리해라.
3. 대상의 패키지·테이블·DB·URL·세션 방식에 맞게 화면·Controller·Service·Mapper/XML·SQL을 옮겨라.
4. 필요한 테스트 자산과 URL·메시지·세션·seed 맞춤 항목을 보고해라. 테스트 준비·수정은 스펙 담당자의 별도 작업이며 구현 에이전트는 테스트 파일을 만들거나 수정하지 마라.
5. 확인되지 않은 업무 규칙·권한·DB 의미는 추측하지 말고 "미확인"으로 남기고 질문해라.
6. 제공된 테스트로 단독 테스트와 verify.cmd를 실행하고, ego-browser GUI·대상 DB 확인 결과와 수정 파일·버전·남은 위험을 보고해라. 테스트가 준비되지 않으면 이식을 완료로 보고하지 마라.
```

### 3.3 확인

실행·복사·대상 맞춤·검증은 [기능 시트](feature-porting-sheet.md), 별도 테스트 준비·승인·실행은 [테스트 시트](test-porting-sheet.md)로 확인한다. 실패·미수행 항목의 사유와 남은 위험까지 보고받는다.

## 4. 요청 시 꼭 포함할 것

- Arkive 경로와 대상 프로젝트 경로
- 이식할 기능명과 범위(화면/API/DB/테스트 포함 여부)
- 대상 프로젝트의 패키지·DB 제품·인증 방식
- 대상에서 이미 다른 이름으로 존재하는 테이블·메뉴·URL
- 금지 범위: Arkive 기록·비밀값 이전, 구현 에이전트의 테스트 생성·수정, 테스트 삭제·skip
- 완료 기준: 승인·준비된 테스트와 전체 `verify.cmd` 통과, ego-browser 화면 확인, 대상 DB 확인. HSQLDB 결과만으로 Oracle/PostgreSQL 이식을 완료로 보지 않는다.
