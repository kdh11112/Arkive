# 변경 검증 근거 보고서

> 이식 구분: 복붙 가능(양식). 빈 양식 그대로 복사해서 작업별로 채운다. 항목별 적용 판단은 본문 가이드대로 한다.

기능 이관, 업무 규칙/권한·API·DB 변경 등의 완료 근거를 기록한다. 해당 없는 항목은 생략하거나 `N/A`, 필요한데 실행하지 못한 항목은 `미수행`으로 적는다. 민감정보·운영 비밀값은 기록하지 않는다.

기대값은 승인된 Acceptance에서 가져오고 실행·증거 수집은 [검증 절차](../common/verification-standard.md)를 따른다. 같은 결과물은 아래 표에서 연결하고 중복 첨부하지 않는다.

## 최종 확인

- [ ] 요구사항 및 관련 Acceptance Criteria를 확인했다.
- [ ] 필요한 테스트를 수행하고 실제 결과를 기록했다.
- [ ] 필요한 Runtime 검증을 완료했거나, 미수행 사유를 기록했다.
- [ ] 변경 영향 범위를 확인했다.
- [ ] 중요한 결과에 대한 증거와 위치를 기록했다.
- [ ] 남은 위험 또는 후속 작업을 기록했다.
- [ ] 변경 버전을 추적할 수 있다.

완료 판단 시 실패한 항목과 미수행 검증의 영향을 고려하고, 필요한 후속 조치를 남긴다.
