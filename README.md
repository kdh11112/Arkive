# Arkive

> Arkive는 다른 프로젝트에 기능 이식을 편하게 만들기 위해 만든 아카이브/레퍼런스 프로젝트다.
> 새 기능은 Arkive에 축적하고, 타 전자정부프레임워크·Spring·Spring Boot 프로젝트에서 복붙으로 가져간다.
> 프로젝트명·패키지·테이블명·파일 위치·DB 제품(Oracle/PostgreSQL 등)은 이식 대상에 맞게 최소한으로 바꾸는 것을 전제로 한다.

## 가져가는 순서

1. `docs/ai/common/`은 그대로 복사한다.
2. `docs/ai/project/`는 폴더째 복사한 뒤 각 문서 상단의 작성 가이드대로 양식만 채운다.
3. 기능 코드는 화면 → Controller → Service → Mapper → XML → `db/versions` SQL → 설정·의존성 순서로 가져간다.

## 기능 구현 기준 (참조와 개선)

기능을 만들 때 아래를 참고하고, 더 나은 방법이 있으면 그 방법을 사용한다. 똑같이 만드는 게 목표가 아니다.

- eGovFrame 공통컴포넌트 v5.0 가이드: https://www.egovframe.go.kr/wiki/doku.php?id=egovframework:com:v5.0:init_guide
  - 명함관리(cop)·상담관리(uss) 등 업무 규칙·테이블·상태코드의 근거로 사용했다.
- 저장소 내 실측 프로젝트: ADTM, BLMS, gcsms, GIES, GTEMS (pony-main, GCG-master, HTA-main 포함 survey)
  - BLMS 팝업·배너·카테고리·FAQ/Q&A, pony 공지·Q&A, gcsms 당직·엑셀·민원, GTEMS 설문(qestnr)을 CRUD·스키마 패턴 근거로 사용했다.
  - ADTM(지역 JOIN)·HTA(raw JDBC)는 이식 부적합이라 제외했다.

대표 개선 예시:

| 기능 | 참조 | 더 나은 방식 |
| --- | --- | --- |
| FAQ·Q&A 질문 | BLMS/gcsms 단일테이블+타입코드 | 신규 테이블 없이 `BOARD`+`BOARD_TYPE` 재사용 |
| Q&A·메모 상태 | pony `answerStatus` 컬럼 | Q&A는 상태 컬럼 제거(JOIN 판정), 메모는 상태 전이를 SQL 조건으로 강제 (동기화 불일치 제거) |
| 카테고리 트리 | BLMS jstree 라이브러리 | 네이티브 `<details>` + jstree 규격 `tree.json` 병행 (의존성 제거) |
| 메인이미지 | eGov 별도 컴포넌트 | `BANNER`+`POSITION` 통합 |
| 파일 실형식 검증 | 로드맵 Tika案 | `FileTypeUtil` 매직바이트 검사 (의존성 추가 없음) |
| 온라인POLL 중복투표 | 로그인 전제 방식 | 세션 집합 차단 |

## 새 글 알림 (SSE) 화면 설정

- 목록·상세·메뉴 등 전 화면에서 `GET /board/subscribe`로 새 글 알림을 받는다 (`layout.html`).
- 화면별 조절은 해당 페이지 inline 스크립트에 선언한다 (`layout` 스크립트보다 먼저 실행되어야 한다).
- `window.ARKIVE_SSE = { banner: false };` — 이 화면에서는 배너 숨김.
- `window.ARKIVE_SSE = { hideAfterMs: 30000 };` — 30초 뒤 자동 숨김. 기본 0(계속 표시).

- [x] 로그인 (JWT, API용) (JwtUtil + /api/** 필터) — 세션 로그인과 병행. 화면·관리는 세션, 외부 API·모바일은 JWT. 위험: 시크릿·만료시간 환경 분리, 로그아웃 시 블랙리스트(또는 짧은 만료) 정책 선행
