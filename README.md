# Arkive

> Arkive는 다른 프로젝트에 기능 이식을 편하게 만들기 위해 만든 아카이브/레퍼런스 프로젝트다.
> 새 기능은 Arkive에 축적하고, 타 전자정부프레임워크·Spring·Spring Boot 프로젝트에서 복붙으로 가져간다.
> 프로젝트명·패키지·테이블명·파일 위치·DB 제품(Oracle/PostgreSQL 등)은 이식 대상에 맞게 최소한으로 바꾸는 것을 전제로 한다.

## 가져가는 순서

1. `docs/ai/common/`은 그대로 복사한다.
2. `docs/ai/project/`는 폴더째 복사한 뒤 각 문서 상단의 작성 가이드대로 양식만 채운다.
3. 기능 코드는 화면 → Controller → Service → Mapper → XML → `db/versions` SQL → 설정·의존성 순서로 가져간다.

## 운영 메모

- actuator (운영 모니터링): `health/info/metrics`를 노출한다. 서버 생존·DB 상태·요청 수·JVM 메모리를 본다. 민감 엔드포인트는 내부망으로 제한이 원칙이다.

## 새 글 알림 (SSE) 화면 설정

- 목록·상세·메뉴 등 전 화면에서 `GET /board/subscribe`로 새 글 알림을 받는다 (`layout.html`).
- 화면별 조절은 해당 페이지 inline 스크립트에 선언한다 (`layout` 스크립트보다 먼저 실행되어야 한다).
- `window.ARKIVE_SSE = { banner: false };` — 이 화면에서는 배너 숨김.
- `window.ARKIVE_SSE = { hideAfterMs: 30000 };` — 30초 뒤 자동 숨김. 기본 0(계속 표시).

## 만들어야 하는 기능 (로드맵)

설명 + 위험·주의점 함께 적는다. 순서는 의존성 순이다.

- [x] 게시판 (CK·토스트 에디터, HWP 복붙, 에디터 이미지 업로드)
- [x] 페이징 (CK: 전자정부 오프셋, 토스트: 커서+더보기)
- [x] 이전글/다음글
- [x] 공통코드 관리
- [x] 파일 업로드 (멀티파트·TUS·드롭존, temp→확정 2단계)
- [ ] 로그인 (세션 기반, 실패 잠금) — 모든 로그·권한의 전제. 위험: 비밀번호 평문·무솔트 저장 금지(bcrypt), 실패 잠금 미적용 시 무차별 대입 노출
- [ ] 댓글 (로그인 이후. 1단, 대댓글 없음)
- [ ] 관리자 로그인 (관리자 전용 진입·세션 분리) — 위험: 일반 세션과 섞이면 권한 우회. 진입 URL·세션키 분리 필수
- [ ] 사용자 관리 (등록·수정·삭제·비밀번호 초기화) — 위험: 초기화 규칙(아이디+1234 같은 고정값) 금지, 변경 이력 남기기
- [ ] 로그인 (OAuth 2.0, 소셜: 네이버·카카오) — 위험: 클라이언트 시크릿·콜백 URL 환경 분리, 기존 세션과 회원 매핑 정책 선행
- [ ] 2차인증 (TOTP) — 의존성(pom)은 있음. 위험: OTP 키 분실 시 복구 절차(관리자 초기화) 없이 도입 금지
- [ ] 권한관리 (메뉴별 조회·등록·수정·삭제) — 위험: 화면 숨김만으로 끝내지 말고 서버(인터셉터)에서 강제. ADTM처럼 컨트롤러마다 분기 박기 금지
- [ ] 로그관리 (로그인·메뉴·개인정보 열람·다운로드) — 위험: 로그에 비밀번호·주민번호 등 원문 기록 금지. 개인정보 로그는 별도 보관주기 적용
- [ ] 개인정보 보호 (마스킹, 열람·다운로드 로그 연계) — 위험: 목록·엑셀·상세 전부 마스킹 누락 지점 점검. 마스킹은 표시용, 원문은 DB 권한으로 통제
- [x] 글쓰기 본문 sanitize (Lucy core 직접 사용. 서블릿 필터는 jakarta 미지원이라 제외) — 위험 해소됨. script·비디오외 iframe·이벤트 속성 제거, 표·이미지·style 유지
- [ ] 통계 (게시판·접속 현황)
- [ ] 공지 고정 (외부 페이지 만들 때 함께. 상단 고정글)
- [ ] Spring Batch (대량 집계·일괄 발송. 규모 커지면 도입)
- [x] 실시간 알림 SSE (새 글 등록 시 목록 배너. SseEmitter, 별도 의존성 없음)
- [ ] WebSocket (양방향 필요 시. 채팅 등) — 위험: Oracle 함수 기반 쿼리 그대로 이식 금지(HSQLDB/PG 문법 확인)
- [ ] SMS 보내기 (알리고 기반, 인증번호·알림) — 위험: API키 코드 하드코딩 금지(환경 분리), 발송 실패 재시도·요금 폭탄(루프 발송) 방지
- [ ] Mail 보내기 + @Async (spring-boot-starter-mail 활용, 블로킹 분리) — 위험: SMTP 계정 노출 금지, 대량 발송 시 스팸 차단 정책 확인
- [ ] ApplicationEvent 기반 로그 (업무 코드 오염 없이 기록) — 로그 도입 시 같이 적용. 위험: 비동기 유실 가능성은 감안(트랜잭션 분리)
- [x] Swagger (springdoc API 문서: /swagger-ui.html) — 위험: 운영 공개 시 민감 API 노출. 내부망 제한 또는 비활성화 검토
